Mac: Mac mini (Apple M4, macOS 15.6).

## Лаунчер

**Сделано по ТЗ**
- Только горизонтальная ориентация; экран не гаснет (флаг окна, плюс опция wake lock в других приложениях).
- Жесты: вверх/вниз — карточки (по кругу), влево — приложения, вправо — настройки; долгое нажатие на карточку — её настройки.
- Карточки:
  - **главная** — часы и календарь пополам, часы аналоговые или цифровые;
  - **погода** — Open-Meteo, °C/°F/K, прогноз на 12 часов и на 7 дней, анимированное небо, сделано по референсу;
  - **календарь** — с выбором месяца;
  - **часы** — 4 циферблата по референсам 2–4;
  - **нагрузка Mac**\* — CPU, GPU, память, сеть;
  - **плеер**\* — трек, обложка, пауза, перемотка, громкость;
  - **созвоны**\* — выключение микрофона и звука, аудиовизуализатор.
- Список приложений: поиск, фильтры, сетка или список, сортировка, скрытие, удаление.
- Стиль iOS 18: шрифт Inter, контролы как в iOS, настройки в виде iPad Settings.
- Темы: светлая, тёмная, авто; 8 цветовых схем (iOS, Catppuccin, Gruvbox, Nord, Dracula, Solarized, Tokyo Night, Rosé Pine);
  свои темы в JSON (добавляются через adb, компаньон или «Создать из текущей»).
- Раздел настроек собран из пунктов ТЗ (14 разделов).

**Сверх ТЗ:** ночной режим в красном (по расписанию или датчику), сдвиг пикселей от выгорания, возврат к первой
карточке после бездействия, русская и английская локализация, погода через Mac для телефона без интернета,
WifiLock для стабильного Wi-Fi.

**Технические решения**
- Без AndroidX и Compose: только `View`/`Canvas`, APK 458 КБ, анимации идут только на видимой карточке.
- Android 6 не доверяет текущим корням Let's Encrypt (open-meteo): в APK встроены ISRG Root X1/X2,
  есть прокси через компаньон и запасной HTTP.

## Компаньон для macOS
- Строка меню (без Dock): статус, проверка подключения, открыть лаунчер, отправить тему, настройки, журналы.
- Сам находит adb и устройство, делает `adb forward`, переподключается.
- Данные: CPU, GPU, RAM и сеть (IOKit/mach), трек из Music и Spotify (AppleScript), созвон по процессам с микрофоном
  (CoreAudio, macOS 14.2+), mute микрофона и звука, визуализатор микрофона (AVAudioEngine + FFT).
- Журналы компаньона и лаунчера в одном окне, плюс файл `~/Library/Logs/StandByCompanion.log`.
- Wi-Fi-отладка: включение через USB в один клик, автопереподключение, переход между USB и Wi-Fi,
  восстановление после перезагрузки телефона или смены IP.

### Стабильность Wi-Fi

| Сценарий | Результат |
|---|---|
| Работа по Wi-Fi, 4 минуты без вмешательства | ping в среднем 62–66 мс, максимум ≤ 0,5 с, потерь 0, обрывов 0 |
| `adb disconnect` | восстановление по Wi-Fi за 2 с |
| Wi-Fi на телефоне выключен | переход на USB за ~20 с (до правки таймаута было 12 с на обнаружение + 8 с) |
| Wi-Fi включён снова | возврат на Wi-Fi за ~7 с |
| Телефон потерял режим adb по TCP (`adb usb`, как после перезагрузки) | компаньон сам включил его через USB, Wi-Fi вернулся за 4 с |
| USB | ping 4–5 мс |

Длинный 10-минутный прогон после 21:56 оказался не чистым: в это время компаньон перезапускали, подключали
второй телефон (Pixel 10a) и выключили Wi-Fi-режим в настройках. По логам этого периода найдены и исправлены три проблемы (см. ниже).

## Найденные и исправленные ошибки

| Проблема | Причина | Исправление |
|---|---|---|
| Пустой список приложений | панель подписывалась на загрузку после её окончания | обновление при присоединении к окну |
| Не показывался трек в плеере (пауза работала) | `st` — зарезервированное слово AppleScript | переименование, ошибки AppleScript теперь пишутся в лог |
| Визуализатор не работал | движок звука не тянул вход без выхода; Bluetooth-профиль останавливал движок | подключение к беззвучному микшеру, перезапуск при смене конфигурации |
| Падение компаньона при зависшем `adb connect` | `terminationStatus` у ещё живого процесса | ожидание завершения, SIGKILL |
| Падение компаньона при переключении Bluetooth-профиля | `installTap` с устаревшим форматом | проверка формата до установки |
| Рывки данных, пока Wi-Fi недоступен | `adb connect` блокировал очередь отправки | проверка вынесена в отдельную очередь |
| Обрывы USB во время восстановления Wi-Fi | `adb tcpip` раз в минуту перезапускал adbd | `tcpip` только если TCP-режим выключен, нарастающая пауза до 10 мин |
| «No route to host» у adb при доступном телефоне | macOS «Локальная сеть» не пускает adb-сервер, запущенный другим приложением | компаньон перезапускает adb-сервер от своего имени |
| Ошибка компиляции `scrollY` | свойство случайно переопределяло `View.getScrollY` | переименование в `detailScrollY` |

## Изменения пользователя, сохранённые как есть
- Визуализатор переключён только на микрофон (`Visualizer.update`); системный звук в коде оставлен, но отключён.
- Порядок карточек и настройки на телефоне; в настройках компаньона Wi-Fi-режим выключен,
  на телефоне adb по TCP остаётся включённым (порт 5555).

## Не проверено и ограничения
- Spotify (не был запущен), эмуляция медиаклавиш без плееров, автозапуск при входе, окно «Check Connection» из меню
  (та же проверка из окна настроек работает).
- Самовосстановление adb-сервера при «No route to host» проверено вручную (перезапуск сервера помог),
  автоматическая ветка в коде отдельно не воспроизводилась.
- Готовый компаньон только для arm64: универсальная сборка требует полного Xcode.
- Плеер видит только Music и Spotify: с macOS 15.4 закрыт системный «Сейчас играет».
- Ключ подписи APK и его пароль лежат в репозитории — подходит для личного использования, не для публикации.
- На скриншоте плеера есть обложка альбома, который играл пользователь.
